# Storydex 项目架构说明

更新日期：2026-08-29

本文档是贡献者和维护者参考，说明当前源码树的正式运行架构、主要目录和数据边界。阶段性迁移过程、诊断报告和交接记录不属于公开产品文档，统一保存在本地忽略目录或外部记录中。

## 当前正式架构

Windows 桌面版采用以下链路：

```text
Vue 3 / TypeScript / Vite
          ↓
Tauri 2 桌面壳
窗口、文件选择、预览、单实例、更新和进程生命周期
          ↓
storydex-agentd 独立 Rust sidecar
HTTP/SSE、Agent、项目文件、Git、WIKI、预设、帮助与系统接口
          ↓
Coomi Rust runtime
Provider、会话、工具循环、权限、压缩与恢复
```

Tauri 在启动时拉起 `storydex-agentd`，由 sidecar 选择动态 loopback 端口并生成随机运行令牌。桌面壳验证健康状态后再创建 Vue 窗口；前端通过本地 HTTP/SSE 调用 Rust 服务。退出时先调用带鉴权的 shutdown 接口，超时后由 Windows Job Object 清理整个进程树。

当前 Vue 工作台的 96 个实际 API 消费契约均已由 Rust 后端覆盖。正式 Tauri 安装包和便携包不携带 Python、FastAPI、Uvicorn、Electron、Node 或 npm 运行时。

## 主要目录

```text

├─ apps/
│  ├─ frontend/                 # Vue 工作台及 Tauri 前端桥接
│  ├─ desktop/
│  │  ├─ agent-runtime/         # Windows Rust Agent、Coomi 与 storydex-agentd
│  │  ├─ tauri-preview/         # Tauri 2 正式桌面壳；目录名为迁移期历史命名
│  │  ├─ candidate/             # 本地打包 staging，受 Git 忽略
│  │  └─ release/               # 本地发行产物，受 Git 忽略
│  ├─ backend/                  # 非 Stable 的 Python 后端兼容与测试边界，不进入 Stable 包
│  ├─ android/                  # Android 原生应用与独立 Rust runtime
│  └─ android-frontend/         # Android WebView 前端
```

## 前端

`apps/frontend` 提供 Storydex 主工作台：

- `src/layouts/WorkbenchLayout.vue`：资源栏、编辑区和 Coomi 面板主布局。
- `src/components`：文件树、编辑器、Agent、版本控制、预设、系统设置等组件。
- `src/stores`：工作区、Agent、认证、主题和 UI 状态。
- `src/api`：面向 `/api/v1` 的 HTTP/SSE 客户端。
- `src/desktop`：Tauri 桌面桥接和 updater 适配。

前端不直接获得任意 shell 或文件系统权限。目录选择、路径定位、预览和更新由最小 Tauri capability 暴露；小说项目读写仍通过 `storydex-agentd` 的工作区边界执行。

## Windows Rust 后端

`apps/desktop/agent-runtime` 是 Windows 正式后端与 Agent runtime：

- `storydex-agentd`：HTTP/SSE 入口、鉴权、Agent 控制面以及系统、文件、Git、WIKI、预设和帮助接口。
- `engine`、`providers`、`tools`、`security`、`services` 等 crate：Coomi 执行、Provider、工具、安全策略和 Storydex 领域服务。
- `storydex-coomi-bridge`：由 `storydex-agentd` 按请求启动的 Rust Coomi 执行 bridge；Tauri Stable 直接启动的是 `storydex-agentd`，两者在正式包中并列部署。
- `Cargo.lock`：Windows runtime 的唯一锁定依赖基线。

项目目录的规范化、越界防护、会话隔离和写入约束都在 Rust 服务侧执行。`apps/backend` 不再提供 Agent 产品入口，仅作为非 Stable 的后端兼容与测试边界保留；它不是 Windows Stable 的启动、构建或打包入口。

## Tauri 桌面壳

`apps/desktop/tauri-preview` 虽保留迁移期目录名，但已经是当前 Tauri Stable 源码目录。它负责：

- 主窗口、预览窗口、单实例和命令行打开目标；
- 目录选择、系统路径定位和 Open With；
- 启停 `storydex-agentd`、健康检查、日志和进程树清理；
- Tauri updater 检查、下载和安装；
- NSIS、便携 ZIP 和最小 Rust-only runtime staging。

正式运行 staging 包含 `Storydex.exe`、`storydex-agentd.exe`、`storydex-coomi-bridge.exe` 和 `mingit/`。Vue 资源由 Tauri 打入应用，使用指南和指令模板由 Rust 编译期嵌入。

## Android

Android 使用 `apps/android/agent-runtime` 的独立 Rust workspace 和 `apps/android-frontend`。它与 Windows 共享必要的协议和稳定性修复思路，但不共享入口 crate、提示词、平台工具或锁文件。

## Storydex 小说项目

用户创建或打开的是普通本地目录。典型结构如下：

```text
your-novel-project/
├─ chapters/             # 正文与章节
├─ .gitignore            # 默认忽略 Storydex Agent 运行态
└─ .storydex/
   ├─ project.json       # 项目元数据
   ├─ config/            # 项目配置
   ├─ presets/           # 写作预设
   ├─ characters/        # 角色资产
   ├─ worldbook/         # 世界观资料
   ├─ memory/            # 创作记忆与章节滚动摘要
   ├─ wiki/              # 知识图谱 / LLM WIKI
   ├─ .cache/            # 可删除并重建的本地索引缓存
   └─ .agent/
      ├─ sessions/       # Agent 会话历史
      ├─ plans/          # Agent 计划
      └─ temp/           # Agent 临时文件
```

项目文件是事实源；索引、WIKI 投影、图谱和缓存都必须能够从事实源重建。Storydex 不会自动为小说项目配置远程 Git，也不会自动 push。

## 发布与仓库边界

正式 Windows 发行入口是 `.github/workflows/release-windows.yml` 和 `npm --prefix apps/desktop run package:win`。当前产物为签名 updater 所需的 NSIS 安装包、`.exe.sig`、`latest.json` 和 Rust-only 便携 ZIP。

以下内容不得提交：

- `.env`、API Key、私钥、证书和本地账号配置；
- `node_modules`、Rust `target`、Python 环境、构建产物、缓存和日志；
- 用户小说项目、临时工作区、测试结果和调试输出；
- updater 私钥、Windows 代码签名材料和部署凭据。

公开提交前应检查 `git status --short`。正式发布前还必须完成签名构建、旧版升级、失败恢复和人工回滚验收。
