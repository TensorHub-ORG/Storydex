# 连续写作实测后的修复（2026-10-29）

依据本机 `output/pi-writing-quality-20261029/REPORT.md` 和原始回合、上下文及工具记录。本轮修产品链路，不把六章单次对照当作文风提升的统计证据。前一轮尚未提交的默认写作指导一并交付。

## 已实现

- **正文输出恢复独立于严格字数检查。** 低/中/高推理分别预留 8192/16384/32768 tokens，另给正文按字符估算预算；总上限 65536。目标 1600 字不再受 8192 的总预算限制。空正文或供应商明确截断时，即使关闭严格字数检查也最多恢复一次，预算加倍至上限，从原要求与参考资料重新生成完整章；目标字数、推理档不变，不拼接残稿。恢复和可选字数修订共用一次额外调用额度，界面会说明额外模型调用。完整但偏短/偏长的正文仍按作者的严格检查开关处理。
- **常驻事实与计划。** 默认读根目录章纲/大纲/卷纲/卷摘要/故事设定等约定文件，`.storydex/story-bible.md`、memory 中的 Markdown/TXT 摘要、scripts 与 worldbook。它们不再要求文件名出现在用户提示词里。取最近三章，目录章节、扁平章节和中文章号共用章节索引排序；未保存编辑器稿优先。总预算仍为 40000 字符，常驻材料最多 12000、最近正文最多 16000，逐源记录截断与省略。摘要来自项目已有文件，不额外调用模型编摘要。
- **已确认关系参与创作。** 有图谱/关系文件时先增量刷新本地图谱，再只引用已确认、来源有效的关系；另外核对当前正文或编辑器草稿中的逐字引文。改了候选、删了引文或未确认的关系不沿用旧确认。图谱刷新失败会省略该来源并在回合显示，不阻塞正文生成。逐字匹配仍不等于语义证明。
- **一次替换完整改稿。** `edit_file` 支持 `start_line/end_line`（含两端）及完整 `new_string`，必须携带已读版本 `expected_revision`；保留范围外字节，兼容 CRLF，拒绝旧版本行号。小改仍用原有字符串替换。共享任务提示说明大段改稿应先组成完整替代段，再一次应用。
- **失败稿可恢复。** Storydex bridge 为 `write_file`、`edit_file`、`apply_patch` 记录本回合前后内容。工具轮数耗尽、模型失败或正常取消时，在 `.storydex/.agent/failed-edits/<id>/` 保存原稿、失败稿和清单，再恢复该回合文件改动；补丁的移动和来源身份元数据一起记录。若检测到另一个写入者介入，则保留现场并提示对照存档，不做半套自动恢复。恢复结果进入界面与持久会话，后续模型会先重读文件。
- **连续写作与图谱界面。** 保留作者选择的“按模板生成新章节”，直至手动切换。每轮可展开实际参考文件、字符数、部分加入/未加入及编辑器草稿标记。章节节点显示“章节目录 / 片段”，系统 project 和 chapter-progress 文件不再成为故事节点；复核端点用名称选择，去掉空的 confidence/provider/model/trace 字段，说明引文与关系含义的区别。
- **默认写作指导。** 三端共用 `apps/backend/services/writing_guidance.json`；无主预设默认生效，缺省模块继承默认值，显式关闭和自定义保留。新增对话标签与回应变化、开篇关注点、配角主动性、规则/物件因果建议；不设禁词表，也不要求所有题材都快节奏。关闭全部指导不会附带字数合同或回退默认指导。
