# 可靠性修复交付记录（2026-10-28）

本次整理 10 月 27～28 日的本地修复及四轮 pi 验收成果。各轮修复文档是当时的记录；其中“未提交”“尚未实测”和旧实现说明具有时间边界，不代表本次交付状态。推送与 CI 的最终结果以 Git 提交和 GitHub Actions 对应 SHA 为准。

1. 文件工具与 WIKI 底层：跨进程项目写锁、文件读取版本校验、询问模式审批和委派只读、关系候选审核及投影故障状态。
2. 工作台与 Agent：保存期间输入保护、冲突处理、IndexedDB 大草稿备份、8 MiB 保存边界、独立预览、读取及故事设置竞态、准确错误提示、普通 Agent 任务与显式章节入口、简短字数引导及可选严格检查。补接章节生成的已有项目上下文。
3. 接口盘点与交付证据：覆盖组件内 API 消费，明确三个未实现接口；CI 为盘点测试指定运行时范围，并在 source-policy 执行该测试，避免误触发无关组件全套检查。

协议变更和对应前后端一起提交。原始 Playwright 证据、隔离小说项目、凭证、运行日志和本地研究缓存不进入 Git。

## 验收证据

pi 第四轮报告位于本地 `output/playwright/pi-reliability-round4/REPORT.md`，针对性断言 54/54 通过。真实样本只有两次，不能据此推断模型稳定命中率：

- 引导模式目标 6000 字：一次调用产出 6709 字并写入第一章，无自动修订。
- 严格模式目标 6000 字：一次调用产出 6387 字并写入第二章，满足 5400～6600。
- 设置持久化、Vite 开发模式下 PUT 串行、跨项目等待和错误持续显示通过；多种失败/修订分支另用注入响应核对。
- 对话中的大段候选来自严格检查失败或截断注入，明确标为未写入；两次真实生成均有磁盘证据，并非只输出正文而漏写文件。

前三轮实测还覆盖了真实界面审批、大文件完整加载编辑保存、大草稿刷新恢复、编辑器与 Agent 冲突、浏览器独立预览及 WIKI 审核。

最新上下文修复在第四轮之后：实际模型消息加入最近一章、相关角色/世界观/脚本和编译预设，草稿只作参考，来源及截取情况进入 trace。聚焦测试验证初稿和修订消息确实带入资料；**尚未用真实模型验证连续性改善**，也不自动修复已生成的矛盾正文。详见 [第四轮核对与修复](reliability-round4-review-20261028.md)。

提交前本地聚焦验证包括文件/WIKI/审批 18 项、前端 7 文件 121 项及类型检查；此前最新上下文修复的 Rust 聚焦测试和 Clippy 已通过。CI 负责受影响组件检查，不将这些本地结果表述为完整跨平台验证。
