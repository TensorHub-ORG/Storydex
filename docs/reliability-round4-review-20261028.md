## 发现的实际缺口

1. **显式章节生成没有传递已有项目上下文。** `story_generation.rs` 原先只向 bridge 的 `complete` 传入篇幅 system prompt 和本次用户输入，`tools=[]`；bridge 直接使用该 messages，不恢复 Agent 历史或自行读取项目。角色设定、上一章和已编译预设均未送入本次模型调用。原 TurnContract 的来源描述只记录路径，不能证明模型实际接收了内容。
2. **字数兼容字段与主目标不同步。** PUT 提供主目标时，旧 min/max 仍从 baseline 读取。
3. **项目切换等待阶段缺少状态。** 首次等待草稿及设置队列时还没有设置切换状态，用户看不到等待，也可重复发起切换。

因此第四轮字数及设置同步的 54/54 结论成立于其测试范围，但跨章节事实矛盾不能完全归因于模型质量。基础上下文缺失是代码问题；补上后仍不能保证模型不会写错。

## 本轮实现

- 新增本地上下文读取：最近一个编号章节的正文片段按数字顺序读取；没有编号章节时使用最近的根目录正文文件。当前打开文件可补充，已提交的编辑器脏草稿优先于同路径磁盘版本，仅作为参考，不自动保存。
- 加入名字出现在任务或近期正文中的角色、世界观和故事脚本文件，以及这些目录的 README；加入当前已编译的启用预设。读取不新增模型调用，不接入摘要生成或冲突 Judge。
- 参考正文与预设分别放入实际 user/system 消息；修订复用相同基础上下文。提示要求沿用任务语言、人物资料和已有事实。
- 正文及设定内容总预算 40000 字符，其中近期章节最多 20000，预设最多 8000，单份补充资料最多 4000。超出预算的近期正文保留开头及结尾；超过 512 KiB 的磁盘来源暂不读取。省略、草稿来源、实际选中的内容哈希及字符数进入 trace。只读取项目边界内的文件。
- TurnContract 记录实际上下文来源并进入持久化会话，不再宣称已使用 WIKI、FTS、结构化记忆或主动检索工具。这些能力没有接到这条直接生成路径。
- 提交 `chapterWordCountTarget` 时，将旧 `storyFragmentWordCountMin/Max` 同步到主目标；旧客户端只提交范围的请求保留原兼容语义。
- 打开、创建、初始化项目在等待保存之前就设置进行中状态，失败时释放状态并显示原因；重复项目操作被拦住，已有排队写入仍完成后才切项目。
