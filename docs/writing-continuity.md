# 写前构思与续写记录

Storydex 的 PC Rust 运行时在生成章节前读取项目资料，在正文保存后按项目设置整理人物与线索，供后续章节使用。写前构思与提取观察为模型提供依据，不能保证文学质量或伏笔一定回收。

## 写前构思

打开 Agent 输入区的「故事生成参数」，可调整「写前构思」。它默认开启，普通任务也能访问；继续使用原项目字段 `storyCraftEnabled`，关闭后刷新或修改其他设置不会重新开启。旧项目没有该字段时默认开启，没有新增开关。

PC 端使用「按模板生成新章节」时，开启后按以下顺序处理：

1. 读取本章相关章纲、作者要求、人物状态和近期正文，调用当前供应商与同一模型形成一次短简报。先提取作者明确要求本章发生的事件和仍须保留的分歧，再选本章值得读的经历、人物的牵挂、值得展开的回应与可略写部分；可以是日常相处或独处，不要求冲突升级、成长或反转。
2. 用作者事件原句、简报中的视角、人物、核心场面和既有事实补充检索资料，再将短简报交给同一模型生成正文。检索文字不包含试笔或抽象写法；作者要求、已有事实与候选安排分开，候选构思不进入续写记录。简报只帮助安排重点，正文不逐项汇报。
3. 正文通过基础检查、写入权限和已开启的严格字数检查后保存。该开关不再启动写后诊断、整章修订、独立核对或反馈重修。开启「整理人物与线索」时，保存后再调用一次模型整理记录。

正常一章为构思、正文各一次，共两次调用；关闭「写前构思」时直接生成正文，共一次。开启整理时另加一次。严格字数修订或正文输出恢复的调用另计，不属于自动审稿。构思使用当前模型的低推理档（`low`），输出预算为 8,192 tokens，包含供应商可能的推理开销，不是要求生成等量文字。调用、供应商返回用量、耗时与原始结果保留在执行记录中；未报告的用量不能推断为零成本。

候选创作部分目标约 200—350 字，硬上限为 1,000 字符；加上作者事件合同后总内容不超过 1,400 字符。合同最多包含八项必须发生事件、四项保留分歧，每项绑定作者连续原句；程序检查引文出处、结构和长度，不能证明要求已提取完整。正文简报先列作者要求，再给场面与展开方向及少量易误改事实。人物顾虑、认识变化与呼应按需选取，不要求所有人都有隐情，不强制每章埋设或回收线索。

构思失败、截断或结构校验未通过时，不重试构思，说明原因后沿用作者要求和已有资料继续写作。补充资料读取失败时保留已有资料；取消后停止后续调用与项目写入。保存成功只表示正文通过基础条件，不表示文学效果已经验证。

小说创作可以补全作者未指定、又与既有设定相容的名字、背景、旧事、场面细节与当场选择；前文章节、正式设定和作者明确约束优先。不得为了让方案成立，倒填此前已取得关键同意、资源已到位或关键行动已完成来绕开眼前障碍。作者需要审稿或修改时，可通过普通 Agent 明确指定任务和范围。

## 文风与作者要求

三项默认「小说写作指导」分别覆盖表达、场景推进和事实连续性，可编辑或关闭，与「写前构思」开关独立。本次作者要求优先，其次沿用本书的文风、视角、题材与角色设定。三端共享 `apps/backend/services/writing_guidance.json`；本轮将内容从 1,978 字符缩至 1,678 字符，已保存的自定义提示词不会被强制覆盖。

指导允许人物眼前目标与私心、依恋或顾虑并存，也允许人物尚未准确理解或表达自己。日常相处本身可以建立值得读者在意的关系，不必立即转换为任务收益；关系余波会影响后续回应。心理直写、幽默、平常与紧张按本书需要交错，悲喜可以并存，不规定先轻松后悲伤，也不强求眼泪、反转或固定收尾。旧物件、动作、话语只在与当下有关时增加信息或改变含义，不按章强塞呼应。

本轮参考作者访谈与既有研究后提炼上述设计假设，未引入特定作家的语言、人物或场景模板。来源与推论边界见本地 [研究与机制映射](../output/playwright/story-craft-light-20261104/research/研究与机制映射.md)。2026-11-04 已通过 Playwright 固定 `cline / deepseek-v4.1-flash-1017` 完成六篇开关对照及三章连续创作，共17次请求，无失败或正文恢复。agent 匿名阅读略偏好日常、悬疑开启版，奇幻更偏好关闭版；连续故事有局部关系承接，但奇幻前提未落实、仍有场面矛盾。此为小样本主观判断，非真人盲测，尚未证明稳定文学收益。完整正文、成本与失败边界见 [本轮实测报告](../output/playwright/story-craft-light-20261104/REPORT.md)。

章节上下文自动读取根目录 `文风.md`、`文风样例.md`、`style.md`，以及 `.storydex/style.md`、`.storydex/style-examples.md`。样例中的人物和事件只作为表达示例，不进入本书事实。可以在 `文风.md` 中写：

```markdown
第三人称限知，贴近主角的观察，允许直接写心理判断。
现代日常语体，长短句服从注意力，不统一改成短句。
对白先处理眼前的事，熟人可以省略、误会，也能坦白直说。
争执的余波会影响后续决定，章末允许停在实际结果处。
```

读取还会采用最近正文、章纲、人物资料、已确认关系、世界书及既有伏笔台账。资料有预算，实际来源、哈希、省略与截断情况保留在上下文 trace。

## 自动整理

章节选项中的「整理人物与线索」默认开启，按项目保存。成功保存正文后，额外调用一次同一供应商/模型，以低推理档提取变化。关闭后仍可参考已有有效记录；这与变量/WIKI 的自动更新选项相互独立。

记录保存到 `.storydex/memory/continuity/<章节路径SHA256>.json`，每章一份。目录章节包含同目录的正文 Markdown/TXT 片段，排除 README；平铺章节文件分别处理。

本轮调整提取重点：除行动状态、承诺和线索外，保留会影响后续回应的共同经历、亲近与隔阂，摘要写明涉及的人物、关系对象及触发事件；有明确关系意义的习惯、话语或物件也可记录。不把所有生活细节都标为伏笔，也不把推测写成已确认心意。此处只改变提取指导，记录 schema 与来源校验规则不变。

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 当前记录结构版本为 1 |
| `sources[].path / sha256` | 本章完整来源列表及文件原始字节的哈希 |
| `entries[].kind / key` | 人物具体状态、线索、事件或承诺的稳定名称 |
| `summary / status / characters` | 简短观察、状态及相关人物 |
| `sourcePath / quote` | 支持观察的正文路径及连续逐字引用 |
| `rejectedEntries` | 未通过校验的事项及原因 |

自动提取将正文分成带 `S1`、`S2` 等编号的片段，让模型返回 `evidenceId`，由程序回填路径与原句。指引通常提取 3—6 条、最多 8 条，摘要建议不超过 120 字；输出预算为 16,384 tokens，为供应商推理与结构化输出保留空间。存储格式允许最多 20 条记录、每条摘要 400 字符、引文 2—600 字符。每章最多 20 个正文片段，单源最多 512 KiB，自动整理输入最多 60,000 字符。

保存前取得项目写锁，重新验证来源版本和完整片段清单，再逐条验证结构与引用。混合结果保存合格项，并报告未采用数量；全部条目不合格、JSON 无效或来源已变化时保留原记录。失败事项会遮蔽同一事项的旧状态，避免回退到已经过时的观察。

正文先保存。整理失败、取消或输出截断不撤销已保存正文，也不会为整理自动重试。若授权写入范围不包含记录目录，跳过整理并说明原因。整理与正文的调用及用量在 trace 中分别统计。

## 跨章读取与失效

读取按章节自然顺序，对每个 `kind/key` 采用最新观察，再优先选择相关人物、尚未完成的事项与较新变化。没有再次提到的线索不会仅因距离较远而被删除。记录内部选择预算约 5,500 字符，总上下文预算 40,000 字符，计入来源说明；最近正文最多三章、最多 16,000 字符，实际会受其他资料占用影响。

较长章纲优先选取当前章节和相关内容；简短的「继续」也会参考近期正文中的人物与线索。构思的召回内容用于补充资料检索，正文生成使用短简报，完整构思 JSON 保留在 trace。被选原文的来源、行号范围及原文哈希保留在 trace，省略与截断有单独标记。

正文改写、删除、同章增减片段、引用不匹配或编辑器存在未保存改稿时，该章记录失效。最新记录失效仍遮蔽其旧状态；无法识别损坏记录所涉及的事项时，暂不注入整组观察，并在 trace 中报告 `continuity_unavailable`。重新整理后可恢复使用。

编号回填保证原句来自指定片段，不能证明模型选择了充分的证据，也不能证明摘要理解正确。提取观察与作者确认的设定应区分使用，后续章节仍需核对人物知情渠道、因果和线索回收条件。

## 工具展示与普通 Agent

直接章节生成的真实文件操作通过 `WorkspaceOperation` 事件进入原工具瀑布流，以 `read_file` / `write_file` 显示，保留 `origin: runtime`。未保存草稿的读取标记为 `source: editor_draft`；编译后的虚拟预设不显示为文件读取。只有实际保存成功才显示写入成功。旧会话没有操作事件时，不根据参考路径补造调用。

普通 Agent 使用只读工具 `StorydexContinuityRead` 查询观察；传入本章 `sourcePaths` 可获取整章来源、哈希、记录模板和目标路径。指引要求续写/改稿前核对记录，实质改稿后用原生文件工具保存新记录并再次查询核验。该路径依赖模型遵循指引，权限与失败恢复沿用原生 Agent 机制。

普通 Agent 开启「写前构思」时，通过只读工具 `StorydexCraftRead` 取得相关资料与构思指导；工具继承本轮编辑器草稿，不把磁盘旧记录当成草稿的新事实。本轮已读资料直接复用，工具本身不调用模型、不写入项目，也不认证文学质量。Agent 在既有回合中简短构思后写作，不自动启动写后审稿、全章重写或核对循环；已有作者确认方案直接沿用，一处明确修改直接编辑，不另写构思表或强制增加固定调用。作者主动要求检查、复稿时，可参考工具提供的 `reviewGuidance`，用原生编辑工具处理指定范围。普通问答和资料整理不执行写作流程；关闭开关后，作者明确要求的构思或审稿任务仍可执行。

三端共享默认写作指导，前端和 Python 兼容接口保留项目开关；上述自动写前构思与写后整理链路接入 PC Rust 运行时。Python/Android 生成器尚未接入相同自动流程。
