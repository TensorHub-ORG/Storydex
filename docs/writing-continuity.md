# 文风与续写记录

Storydex 的 PC Rust 运行时在生成章节前读取项目资料，在正文保存后按项目设置整理人物与线索，供后续章节使用。写作指导与提取观察为模型提供依据，不能保证文学质量或伏笔一定回收。

## 文风与作者要求

三项默认「小说写作指导」分别覆盖表达、场景推进和事实连续性，可编辑或关闭。本次作者要求优先，其次沿用本书的文风、视角、题材与角色设定。指导允许心理直写、长短句变化、日常对白和叙述者判断；情绪应影响人物选择，线索重现应带来新的信息或后果。

章节上下文自动读取根目录 `文风.md`、`文风样例.md`、`style.md`，以及 `.storydex/style.md`、`.storydex/style-examples.md`。样例中的人物和事件只作为表达示例，不进入本书事实。可以在 `文风.md` 中写：

```markdown
第三人称限知，贴近主角的观察，允许直接写心理判断。
现代日常语体，长短句服从注意力，不统一改成短句。
对白先处理眼前的事，熟人可以省略、误会，也能坦白直说。
争执的余波会影响后续决定，章末允许停在实际结果处。
```

读取还会采用最近正文、章纲、人物资料、已确认关系、世界书及既有伏笔台账。资料有预算，实际来源、哈希、省略与截断情况保留在上下文 trace。

## 自动整理

章节选项中的「整理人物与线索」默认开启，按项目保存。成功保存正文后，额外调用一次同一供应商/模型，以低推理档提取变化。关闭后仍可参考已有有效记录；这与变量/WIKI 的自动更新选项相互独立。

记录保存到 `.storydex/memory/continuity/<章节路径SHA256>.json`，每章一份。目录章节包含同目录的正文 Markdown/TXT 片段，排除 README；平铺章节文件分别处理。

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 当前记录结构版本为 1 |
| `sources[].path / sha256` | 本章完整来源列表及文件原始字节的哈希 |
| `entries[].kind / key` | 人物具体状态、线索、事件或承诺的稳定名称 |
| `summary / status / characters` | 简短观察、状态及相关人物 |
| `sourcePath / quote` | 支持观察的正文路径及连续逐字引用 |
| `rejectedEntries` | 未通过校验的事项及原因 |

自动提取将正文分成带 `S1`、`S2` 等编号的片段，让模型返回 `evidenceId`，由程序回填路径与原句。指引通常提取 3—6 条、最多 8 条，摘要建议不超过 120 字；输出预算为 8192 tokens。存储格式允许最多 20 条记录、每条摘要 400 字符、引文 2—600 字符。每章最多 20 个正文片段，单源最多 512 KiB，自动整理输入最多 60,000 字符。

保存前取得项目写锁，重新验证来源版本和完整片段清单，再逐条验证结构与引用。混合结果保存合格项，并报告未采用数量；全部条目不合格、JSON 无效或来源已变化时保留原记录。失败事项会遮蔽同一事项的旧状态，避免回退到已经过时的观察。

正文先保存。整理失败、取消或输出截断不撤销已保存正文，也不会为整理自动重试。若授权写入范围不包含记录目录，跳过整理并说明原因。整理与正文的调用及用量在 trace 中分别统计。

## 跨章读取与失效

读取按章节自然顺序，对每个 `kind/key` 采用最新观察，再优先选择相关人物、尚未完成的事项与较新变化。没有再次提到的线索不会仅因距离较远而被删除。记录预算约 5,500 字符，总上下文预算 40,000 字符；最近正文最多三章、最多 16,000 字符，实际会受其他资料占用影响。

正文改写、删除、同章增减片段、引用不匹配或编辑器存在未保存改稿时，该章记录失效。最新记录失效仍遮蔽其旧状态；无法识别损坏记录所涉及的事项时，暂不注入整组观察，并在 trace 中报告 `continuity_unavailable`。重新整理后可恢复使用。

编号回填保证原句来自指定片段，不能证明模型选择了充分的证据，也不能证明摘要理解正确。提取观察与作者确认的设定应区分使用，后续章节仍需核对人物知情渠道、因果和线索回收条件。

## 工具展示与普通 Agent

直接章节生成的真实文件操作通过 `WorkspaceOperation` 事件进入原工具瀑布流，以 `read_file` / `write_file` 显示，保留 `origin: runtime`。未保存草稿的读取标记为 `source: editor_draft`；编译后的虚拟预设不显示为文件读取。只有实际保存成功才显示写入成功。旧会话没有操作事件时，不根据参考路径补造调用。

普通 Agent 使用只读工具 `StorydexContinuityRead` 查询观察；传入本章 `sourcePaths` 可获取整章来源、哈希、记录模板和目标路径。指引要求续写/改稿前核对记录，实质改稿后用原生文件工具保存新记录并再次查询核验。该路径依赖模型遵循指引，权限与失败恢复沿用原生 Agent 机制。

三端共享默认写作指导，前端和 Python 兼容接口保留整理开关；上述写后自动整理链路接入 PC Rust 运行时。Python/Android 生成器尚未接入相同自动流程。
