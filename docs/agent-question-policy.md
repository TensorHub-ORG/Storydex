# Agent 提问与调用开销

PC Agent 默认先利用对话、已给出的答案、项目约定和文件解决不确定性。低风险、可逆的小细节可以采用符合请求的合理默认，必要时简短说明后继续。只有无法从已有资料消除、且明显影响结果的关键歧义才向作者提问，例如互相冲突的要求或未确定的主要剧情方向。

用户已经要求写作、修改或整理时，开始执行、保存结果、继续完成任务不应各自再成为确认点。构思和进度说明也不要求逐项批准。当前必要的问题合并为一批，可在问题面板切换查看，选择选项或直接输入回答后一次提交。取消不表示接受推荐答案。

工具权限是另一条边界。「询问确认」模式仍会对需要批准的写入弹出确认；拒绝、取消以及用户指定的只读范围继续生效。用户主动启用的预设和技能可能附带更具体的确认要求。

## 回答问题是否多调用一次模型

答案通过 `/coomi/approval` 返回正在等待的 `request_user_input` 工具，作为工具结果写入同一个 Agent 会话。下一次模型调用使用答案继续任务；没有独立的“先同步答案，再重新开始执行”模型请求。一批中的多个问题全部回答后才继续模型回合。

需要区分另外几种调用：

| 场景 | 调用情况 |
| --- | --- |
| PC「生成新章节」，构思、整理都关闭 | 通常正文一次 |
| 开启「写前构思」 | 正文前增加一次当前模型的短构思 |
| 开启「整理人物与线索」 | 正文保存后增加一次当前模型的记录提取 |
| 两项都开启（默认） | 通常共三次：构思、正文、记录提取 |
| 普通 Agent 写作/修改 | 按实际工具循环调用；构思和记录整理可增加工作，但没有固定三次规则 |
| 上下文接近容量上限 | 可能额外调用模型压缩历史，不是每次问答都会发生 |

上表不包含输出恢复、严格字数修订、供应商重试等异常或附加路径。开关位于 Agent 输入区的「故事生成参数」，按项目保存。此次提问策略调整保留这些开关的既有行为。

## 设计依据与验证边界

参考 [OpenAI Codex Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)（2026-11-04 获取）：先主动收集上下文，以合理假设推进，真正受阻时再澄清。该文是提示与运行流程的参考，不证明任意 Codex 客户端的快捷键或内部调用次数。

本项目的调用结论来自 `storydex-agentd/src/chat.rs`、`storydex-agentd/src/story_generation.rs`、`storydex-bridge/src/main.rs` 和 `engine/src/agent.rs`。策略通过共享系统指导与工具说明生效，不对模型设置固定提问次数，也不自动替用户作出关键选择。具体提问频率仍受模型、任务与已启用预设影响。
