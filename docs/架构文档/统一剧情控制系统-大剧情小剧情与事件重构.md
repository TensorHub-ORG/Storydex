# 统一剧情控制系统：大剧情、小剧情与事件重构

## 1. 目标

本次重构把剧情推进从“模型自行判断是否换阶段”改为“程序状态机调度，模型负责创作和提交证据”。系统需要同时保证：

- 主线不会长期停留在引子或原地打转。
- 每个归档剧情片段都属于一个可追踪的小剧情。
- 随机事件、人物、悲剧和爽点服务于当前剧情，而不是另开无关支线。
- 风格预设只控制表达，不能覆盖事实、剧本和推进约束。
- 模型漏报阶段切换时，程序仍能按已完成小剧情自动推进。
- 达到硬上限却未收束时，整轮拒绝，不写章节、不更新状态。

## 2. 三层剧情模型

剧本管理采用三级架构：**阶段 → 大剧情 → 小剧情**。一个阶段下可挂多个大剧情，一个大剧情下可挂多个小剧情。阶段和大剧情都是大框架指导，只有小剧情承载具体剧情内容。

### 2.0 阶段

阶段是最上层的框架条目，用于把长篇故事切成若干宏观段落（例如「少年离乡」「城邦风波」）。

阶段**不参与状态机**：它没有阶段流转、没有背景时钟、没有片段预算，也不会被推选为「主剧本」。它只提供两件事——阶段目标（写在 `defaultRoute`）与阶段完成标志（写在 `completionCondition`）——作为顶层方向和边界注入上下文。

这样切分是刻意的：大剧情已经有一套经过验收的 5 阶段状态机和冻结预算，在其上再加一层状态机会让推进逻辑出现两个真相源。阶段只做框架，因此推进逻辑完全不受影响。

上下文注入规则：**只注入当前大剧情所属的那一条阶段**，且占用独立配额，不挤占大剧情的 3 条额度。

大剧情的 `parentId` 允许为空，表示「未分组」——旧项目无需迁移即可照常运行。

### 2.1 大剧情

一个大剧情对应一个阶段性主线剧本，是约束框架，不直接替代具体故事内容。它通过 `parentId` 指向所属阶段。

大剧情阶段严格顺序为：

```text
引子（可关闭） -> 开端 -> 发展 -> 高潮 -> 结局 -> 完成
```

大剧情阶段按“已完成且验收通过的小剧情数量”推进，不再按模型报告的阶段或普通回合数推进。

### 2.2 小剧情

小剧情是实际承载情节的唯一结构化单元，采用：

```text
开端 -> 发展 -> 高潮 -> 结局
```

同一时间只允许一个活动小剧情。每个可归档剧情片段必须且只能执行一次以下操作：

- `create`：创建当前小剧情。
- `progress`：推进当前小剧情一个有效片段。
- `resolve`：以成功、失败或代价完成当前小剧情。
- `abandon`：明确放弃当前小剧情，不计入阶段完成数。

小剧情必须保存目标、阻力、退出条件、主线贡献、类型和冻结后的片段预算。

### 2.3 独立事件

随机事件、人物遭遇、悲剧和爽点默认是原子插入，不占用小剧情数量。只有在同一轮正式提交 `subArcUpdates.create`，并满足小剧情完整字段要求后，事件才升级为小剧情。

## 3. 数量和动态预算

### 3.1 大剧情规模

| 预设 | 小剧情总数 | 默认倾向 |
| --- | ---: | --- |
| 快速 | 5-10 | 快速小剧情为主 |
| 均衡 | 15-20 | 标准小剧情为主 |
| 详细 | 25-30 | 标准和重点小剧情为主 |
| 自定义 | 用户配置 | 自定义阶段、片段和比例 |

用户可分别设置引子、开端、发展、高潮、结局需要的小剧情范围。启用的每个阶段至少需要一个小剧情。

### 3.2 小剧情类型

| 类型 | 默认片段范围 | 用途 |
| --- | ---: | --- |
| 快速 | 1-2 | 赶路、交接、短冲突、直接结果 |
| 标准 | 3-5 | 常规局部目标和完整四要素 |
| 重点 | 6-9 | 关键关系、重大冲突、高潮承载 |

允许动态类型调整时，一个小剧情最多调整一次类型。调整后冻结新预算；如果新类型的硬上限低于当前进度，则拒绝调整。

### 3.3 预算快照

新大剧情建立时，程序使用稳定种子和近似钟形抽样生成一次 `budgetSnapshot`：

- 固定大剧情总目标。
- 固定每个阶段的目标和硬上限。
- 固定三类小剧情的片段范围和类型比例。
- 固定是否允许提前完成、类型调整和阶段收束保留数。

后续修改默认配置不会悄悄改变正在执行的大剧情。用户必须点击“应用到当前大剧情”；应用时不会把目标或上限降到已完成数量以下，也不会使一个没有活动小剧情的阶段立即越过边界。

## 4. 强制状态机

### 4.1 小剧情推进

剧情模式生成后，程序先验证正文证据，再事务式更新小剧情：

1. `create` 必须从开端建立，且填写目标、阻力、退出条件、里程碑和大剧情贡献。
2. `progress` 每轮只增加一个片段，片段阶段由程序根据预算自动计算。
3. 达到硬上限前一轮，计划强制要求 `resolve`。
4. 继续提交 `progress` 会被拒绝，计数不变，章节不入档。
5. `resolve` 达到最小预算且结果有正文证据后，小剧情进入完成列表。

### 4.2 大剧情推进

小剧情完成后，程序把它计入当前大剧情阶段：

1. 读取冻结的阶段目标和最大值。
2. 已完成数达到目标或硬上限后，程序自动切换到下一阶段。
3. 模型的 `phaseTransition` 只作为允许提前结束时的建议，不能决定或跳过阶段。
4. 模型漏写 `phaseTransition` 不影响正常顺序切换。
5. 结局阶段最后一个小剧情需要足够强的胜负、代价或后果证据，否则不能完成大剧情。

### 4.3 防拖沓门禁

连续没有主线实质变化达到设置阈值后，下一轮进入严厉推进：

- 必须兑现既有里程碑、关闭路线或产生不可逆变化。
- 主线压力必须主动进入玩家当前局面。
- 新人物、新线索、换场景、讨论和氛围不能冒充推进。
- 阶段进入收束窗口后，优先关闭既有矛盾，不再开启无关支线。

## 5. 统一回合协同顺序

```text
玩家输入
  -> 读取大剧情预算、当前小剧情、剧本和记忆
  -> 程序生成本轮 DirectorPlan
  -> 随机遭遇按计划允许类型抽样
  -> 风格预设作为低优先级表达约束
  -> Agent 动态检索历史章节和结构化记忆
  -> 模型输出正文、行动建议、状态增量
  -> 正文证据校验
  -> 小剧情硬门禁和大剧情状态机验收
  -> 写 pending-commit
  -> 写章节
  -> 写导演状态、记忆、时间和剧本状态
  -> 清理 pending-commit
```

优先级固定为：

```text
事实和玩家权限 > 程序状态机 > 阶段框架 > 主剧本 > 当前小剧情 > 记忆与检索 > 随机遭遇 > 风格预设
```

阶段排在主剧本之上，是因为它界定边界（主剧本不能越出所属阶段的方向）；但它排在程序状态机之下，且**不能作为本轮情节来源**——本轮里程碑只能由唯一的主剧本承担。

## 6. 标准剧本格式和目录

```text
.storydex/
  scripts/
    index.json
    stage/
      <阶段>.md
    major/
      <大剧情>.md
    minor/
      <major-id>/
        <小剧情>.md
    imports/
      <时间戳>-<原文件>
  director/
    state.json
    event-log.jsonl
    pending-commit.json
  memory/
    state.json
```

标准阶段文件只包含阶段目标（`defaultRoute`）和阶段完成标志（`completionCondition`），**没有状态机、没有背景时钟、没有预算快照**；它在上下文里以「阶段框架」角色注入，只有当前大剧情所属的那一条会被注入。标准大剧情文件包含 `parentId`（指向所属阶段，可为空）、前提、目标、核心阻力、完成条件和动态预算。标准小剧情文件包含 `parentId`（指向所属大剧情）、所属大剧情阶段、小剧情类型、片段预算、局部目标、阻力、主线贡献和原始内容。

## 7. 旧剧本格式化重构

剧本管理中的旧格式条目提供“格式化重构”：

1. 读取标题、Markdown 章节或段落。
2. 按当前大剧情预算生成确定性的拆分预览。
3. 只整理已有内容，不凭空补写缺失小剧情。
4. 用户确认后把原文件备份到 `imports/`。
5. 写入标准大剧情和候选小剧情文件，同步 `index.json`。
6. 候选小剧情标记为 `proposed` 和 `pending`，可继续人工修改。
7. 原始条目标记为只读备份，禁止重复重构或重新激活。
8. 写文件失败时删除本次已创建文件并恢复内存索引。

只有大剧情条目可以被格式化重构：阶段本身就是框架文本，小剧情已经是叶子，两者都不提供重构入口。

## 8. 持久化和一致性重建

剧情状态的预算和计数属于程序所有，包括：

- `budgetSnapshot`
- `phaseMinorCompleted`
- `fragmentBudget`
- `fragmentCount`
- `effectiveFragmentCount`
- `minorTypeChanged`
- 阶段、回合计数和已完成阶段

章节编辑触发一致性重建时，模型可依据章节更新目标、阻力、线程、事实和后果，但同一剧情 ID 或标题对应的上述机械字段必须从旧状态保留。重建不能把发展阶段重置为引子，也不能清空已完成小剧情数量。

项目初始化使用项目根目录和单一 Promise 锁，防止设置页、会话恢复和一致性重建并发读取后，用较旧的文件结果覆盖刚提交的导演状态。

## 9. 验收基线

必须持续通过以下回归场景：

- 引子目标为一个小剧情；小剧情完成；模型不提交 `phaseTransition`；程序仍进入开端。
- 小剧情达到片段硬上限；模型继续 `progress`；审核拒绝，片段数不变，不归档章节。
- 有主线变化但漏写小剧情增量；审核拒绝，不归档章节。
- 随机事件没有升级为小剧情；不增加阶段完成数。
- 小剧情类型允许调整一次；第二次调整被拒绝。
- 一致性重建更新叙事字段，但保留预算、阶段和计数。
