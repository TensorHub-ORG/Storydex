# 测试故事001：剧情拖沓诊断与重构方案

诊断来源是 2026-08-19 通过 USB 只读导出的手机项目副本。原项目未被修改；完整备份位于本机临时诊断目录。

## 一、确认的问题

1. 最新四个片段只完成了“桥西度过第一夜”这一项：之后依次新增探水女子、重复向接应汇报、再次递交已经交过州衙的账外线索。主目标“回东岸、确认铁牙队下落”没有得到可验证进展。
2. 导演连续五轮记录 3～5 分并多次标记 `milestone`，但 `stagnationCount=0`。路线、风险和身份变化被错误当作阶段里程碑，导致纠偏机制从未启动。
3. 启用剧本共有七个且全为 `active`，包括下一阶段的 `009_第二波兽潮` 和结局分支 `010_何去何从`；所有索引完成条件、默认路线又是空值。多个未来路线同时争夺模型注意力。
4. `007_第一段高潮_兽潮之夜` 已包含完整真相、日程、反转和完成条件；`008_防务旧约与州衙密令` 大量重复相同幕后真相。二者与结构化记忆重复注入。
5. 记忆已有 86 条，近期大量记录粮食、布条、伤药、脚印、重复报信等一次性流水账；幕后真相也以普通 `objective` 事实混入记忆，既消耗上下文，也存在向玩家泄漏风险。
6. `chapters/202608191818/202608191818-004.md` 的正文前保存了大段英文模型规划、自我检查和 JSON 草拟过程。这是污染章节，不能再作为可靠剧情正文直接进入上下文。
7. 三模式目录存在多个零消息会话文件，证实旧版本模式切换曾错误落盘空会话。

## 二、建议的数据重构

重构前保留完整备份，然后按顺序执行：

1. 隔离 `202608191818-004.md`，从实际中文小说段落重新生成干净章节；重新计算 frontmatter `summary`，并把对应记忆增量标记为待复核。
2. 把 `007_第一段高潮_兽潮之夜` 设为唯一主剧本；`008_防务旧约与州衙密令`、`001_州衙查网` 作为两个背景时钟。`009`、`010` 改为 `pending`；其余已耗尽作用的剧本改为 `completed` 或保持禁用。
3. 给前三个有效剧本填写索引级 `completionCondition` 和 `defaultRoute`，不要只把条件写在 Markdown 正文里。
4. 将重复幕后真相从普通记忆移出，权威真相只保留在主剧本/导演私有状态；普通记忆只保留已经发生、玩家可知或连续性必须使用的状态。
5. 合并一次性流水事实，例如把粮食、药瓶、布条和伤势压成一条“当前资源与伤势”；把连续三次水位确认压成一条“截至当前仍无回东岸通路”。
6. 重建导演主线，使其绑定 `007`，当前阶段目标改成可验收结果，而不是“再探一次”：确认铁牙队生死或位置、关闭一条错误路线、让兽潮第一波产生胜负与代价、让玩家留下参与痕迹。

## 三、下一段剧情的验收标准

- 不再新增与主线无关的人物、刀痕、传闻或幕后组织。
- 至少关闭一条现有路线，或取得铁牙队下落的直接证据。
- 若发生随机遭遇，它必须承载主剧本里程碑或既有后果，不得成为新支线。
- 文风预设可以要求第一人称、白描和留白，但不能把“实质变化”改写成气氛、盘账或重复对话。
- 未满足以上条件时，导演不得清零停滞，下一轮必须提升为更强的施压或不可逆变化。

## 四、本轮程序修复对该项目的影响

新版只注入一个主剧本和两个背景时钟；`pending/completed` 不进入剧情有效剧本上下文。线索/关系不再算实质主线变化，单纯出现一条新路线也不能满足里程碑。随机遭遇取得明确的导演职责，核心上下文优先于大体量世界观文件，检测到模型规划泄漏时整轮不会归档或推进状态。
