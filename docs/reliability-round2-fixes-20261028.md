# 第二轮实测问题修复记录（2026-10-28）

依据 `output/playwright/pi-reliability-round2/REPORT.md`、`findings.json` 和对应实现，第二轮新发现的 N1～N5 均需要修改代码。本次保留前轮工作区改动，完成以下修复；没有提交、推送或改写 pi 的历史实测报告。

## 修复与边界

| 问题 | 根因与改动 |
| --- | --- |
| N1 精确目标无法持久化 | store 构造和规范化设置请求时遗漏了 `preciseWordCountEnabled`、`chapterWordCountTarget`，现已补全。精确开关和目标参与项目设置同步。 |
| N5 设置竞态 | 设置 PUT 串行执行，每次在已确认状态上合并 patch；旧 GET 响应失效。面板关闭等待在途保存结束再同步，旧请求失败不能回滚后一次选择，连续失败回到已确认值。切项目先完成旧项目设置写入，切换过程中不向新项目发送旧设置。 |
| N3 大草稿丢失、导航阻断 | 草稿改存 IndexedDB，保留全文、保存基线、冲突版本和文件保存错误，不再用 localStorage 存大正文。旧备份在同一事务中迁移，提交成功才删除旧键；迁移、读写失败保留已有备份。快速输入合并排队，切项目等待最新备份。普通切文件不会被备份异常阻断。 |
| N3 错误短暂消失 | 保存错误绑定到具体文档，后台轮询不再清掉它。备份失败显示持续提示和重试按钮；备份未完成或失败时注册浏览器离开提醒。备份失败时保留内存草稿，阻止会清空当前项目内存的切换。 |
| N2 高推理耗尽预算、空正文 | 字数范围与 token 预算分开。正文按字数上限预留 token，另外为推理预留空间，保留用户选择的推理等级。空正文或截断可触发原有的一次完整修订，并增加该次输出预算；仍然最多初稿一次、修订一次。 |
| N4 截断候选缺少提示 | 读取供应商结束原因和响应完成状态，缺少结束原因时用 token 用尽作为兜底。截断即使字数合格也不能落盘；失败回复区分完整候选、不完整片段和没有正文。修订截断、结构/质量校验失败、请求失败或字数更偏离目标时，保留更可用的初稿。 |

草稿补充回归覆盖：重命名同步备份路径，显式删除移除对应备份，保存并关闭的文件不会因后续备份合并而重新出现。嵌套 Vue 响应式元数据在写入 IndexedDB 前转为普通对象，避免 DataCloneError。新窗口尚未打开的备份不会被空编辑器清空。

精确目标仍为 ±10%，没有通过放宽验收范围掩盖生成失败。高推理下，3000 字目标的初始输出上限从 3300 调整为 22984 tokens，6000 字目标从 6600 调整为 29584 tokens；空正文或截断后的修订预算最多翻倍，总上限 65536。预算是生成上限，不是保证消耗或保证字数达标；供应商兼容性、实际耗时和用量需真实复测。校验事件同时保留初稿预算、截断状态和修订响应信息。

IndexedDB 备份仍属于当前浏览器来源或 WebView 的本地存储；不等同于章节已写入项目文件。近 8 MiB 中文草稿的本地恢复已验证，浏览器真实配额及刷新行为交由 pi 验收。原有章节文件 8 MiB 保存限制保持不变。

## 交给 pi 的复测重点

先重新编译 `storydex-agentd`、`storydex-coomi-bridge` 并重启测试后端，前端使用当前工作区源码；保持同一浏览器来源以检查原有草稿迁移。

```powershell
cargo build --manifest-path apps/desktop/agent-runtime/Cargo.toml --locked -p storydex-agentd -p storydex-coomi-bridge
```

1. 从真实界面启用精确目标，设置 3000/6000，立即关闭再打开面板并刷新；核对 PUT、后端设置和章节请求保持一致。快速短→长、延迟或失败的设置请求也看一次。
2. 精确 3000/6000 字配合默认高推理做真实章节生成。检查正文、结束原因、预算、最多一次修订，以及最终磁盘内容。真实生成和故障注入分别记录，不将确定性测试当作真实模型成功。
3. 近 8 MiB 文件完整加载后编辑，切文件、切回、刷新和重开项目，核对尾标、dirty 和磁盘基线。编辑后超限仍须拒绝保存，草稿保留，保存错误不能被四秒轮询清掉。备份失败注入时检查持续提示、重试和导航行为。
4. 覆盖截断、两次空正文、修订请求失败/变差：不完整正文不能落盘；片段应明确提示，完整初稿应保留，确实没有正文时不能声称有候选。
5. 对已通过的审批、保存期间继续输入、Agent 修改冲突和切项目读取各做关键回归即可。
