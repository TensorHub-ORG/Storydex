## 交给 pi 的真实复测清单

先记录当前工作区状态，重新编译 **storydex-agentd 和 storydex-coomi-bridge**，重启对应测试进程与前端，核对源码与进程/构建时间。之前 18086 的服务若仍在运行，其行为不能作为本次修复证据。构建命令：

```powershell
cargo build --manifest-path apps/desktop/agent-runtime/Cargo.toml --locked -p storydex-agentd -p storydex-coomi-bridge
```

仍使用隔离合成项目，按真实操作保留请求、SSE、截图与磁盘证据，区分真实模型和故障注入：

1. **审批**：询问确认模式下，章节生成和普通文件改写都应停住。分别允许、拒绝、取消；拒绝/取消不能写入。至少覆盖 shell 与 WIKI 同步各一次允许；不要用自动批准代替人工批准验收。重复工具调用分别审批。
2. **大文件**：重用约 2.15MB 文件，经分页→完整加载→编辑→保存，检查尾标真正落盘和 dirty 清除。再覆盖接近 8MiB 的文件、编辑后超出上限、大于 8MiB 只读提示。这里 8MiB 是字节限制，不是中文字符数。超限必须保留内存草稿且不改盘。
3. **章节**：显式入口选择短档、单正文文件模板和一个片段，验证请求带 short，允许审批后成功落盘。再测中档及精确目标：若自然发生字数不达标，应显示一次修订，核对调用计数。固定短输出/修订失败需单列为故障注入，不能计作真实模型成功。失败回复中应保留可复制正文，重新打开会话仍可读取。任务结束后发普通改写，不能进入章节字数门禁。
4. **读取与错误**：延迟 A 读取后切 B，B 无旧内容且无残留 loading；旧响应也不能结束 B 正在进行的读取。注入图谱 500，并保证代理返回必要的 CORS 头，让浏览器可读取状态；另单测真正断连/无可读响应，两类文案应有区别。
5. **独立预览**：从编辑器右上角入口打开，核对浏览器弹窗和 Tauri 原生入口分别记录。主窗口草稿不得被自动保存，预览初始内容来自磁盘。复测保存期间继续输入及磁盘冲突。
6. **已通过场景回归**：保留草稿、保存不覆盖后续输入、Agent 修改冲突、普通跨文件操作、WIKI 候选审核至少各一个关键场景。
