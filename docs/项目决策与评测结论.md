# 项目决策与评测结论

更新日期：2026-11-04

本文是 Storydex 当前有效的架构决策和实验结论摘要。历史计划、旧 ADR 和完整评测证据只用于追溯，不再构成开发门禁；出现冲突时，以当前用户目标、仓库代码与测试、本文和最新可复现证据为准。

## 决策的适用方式

- ADR 记录默认架构、取舍原因和风险，不是权限系统，也不是不可修改的规范。
- 开发阶段可以根据缺陷复现、性能数据、代码现状和测试证据调整实现。修改时说明影响范围，并补充与风险相称的验证即可。
- AI 或开发者不得仅以“ADR 冻结”“尚未解冻”“缺少 ADR 授权”或“权限不足”为由拒绝合理的修复、增量更新或性能优化。
- 若新实现与旧决策冲突，应指出冲突并更新当前决策，不应把过时文档当成高于用户目标的限制。
- 只有重大产品取舍、不可逆迁移、可能破坏用户数据以及远端或生产操作需要额外确认。普通局部重构、缓存策略、批处理和性能优化不需要“解冻授权”。

## 当前有效架构边界

### Windows Stable 技术栈

- Windows 正式桌面架构为 `Vue/Vite → Tauri 2 → storydex-agentd → Coomi Rust`。
- `storydex-agentd` 是独立进程，负责 HTTP/SSE、Agent、文件、Git、WIKI、预设、帮助和系统接口；Tauri 负责窗口、桌面权限、更新和进程生命周期。
- 对全部 Vue/TypeScript 源码盘点后，107 个前端消费契约中 104 个由 Rust 覆盖；角色冲突裁定、故事回档和撤销回档三个旧接口仍缺失，详见 [接口盘点](rust-backend-interface-inventory.md)。正常 Stable 路径不得回退到 Python，也不能将缺失接口表述为可用。
- Python/FastAPI/Uvicorn 不进入默认 Stable 构建、打包或更新，且 Python Agent 产品入口已删除；Electron/Node 桌面运行时和旧打包入口已移除。仍需 Python 的后端兼容测试必须显式运行。
- Tauri updater 签名用于验证更新来源和完整性；Windows Authenticode 属于独立且可选的发布者签名。

### Full Access 与执行生命周期

- Full Access 优先保证同一次 Agent 处理连续完成。范围内操作默认自动执行，不退化为逐项审批。
- Git 快照、ChangeSet、写前备份和 Trace 用于恢复与审计；恢复能力不可用时必须可见，但不应伪装成 Story Knowledge 权限错误。
- ExecutionCoordinator 负责 Execution 身份、隔离、防重入、取消传播、生命周期和最终化顺序。HTTP/SSE 只负责传输和可观察性，不拥有业务终态。
- 取消后不得继续发起模型调用或写入项目资产；可信收尾所需的 ChangeSet、Trace 和状态元数据仍可完成落盘。

### Coomi 集成

- Coomi Rust Runtime 是当前唯一通用 Agent 执行基座，Storydex 领域服务与专用工具模块是集成边界。
- Windows 与 Android 分别维护独立 Cargo workspace 和 `Cargo.lock`；通用修复需要分别验证后同步，入口 crate、提示词和平台工具不得混用。
- Windows 开发、测试、Tauri sidecar 和发布环境以 `apps/desktop/agent-runtime/Cargo.lock` 为精确依赖基线，并通过 Rust 测试、接口契约和 packaged smoke 治理升级。
- Python requirements 仅服务于非 Stable 的后端兼容与测试，不定义 Windows Stable runtime 版本，也不应被桌面发布流程打包。

### Story Knowledge、索引与 WIKI

- 项目文件是 Story Knowledge 的事实源；Knowledge Index、WIKI、图谱和时间线是可重建的查询或展示投影，不拥有事实。
- “可重建”只表示投影损坏后能够从事实源恢复，不表示每次修改、每次查询或每次启动都必须全量重建。
- 正常热路径应优先使用增量索引和增量 WIKI 投影，只处理当前 ChangeSet 影响的记录。大项目不得因为条目增多而同步扫描、重算或重写全部条目。
- 明确允许按变更集局部更新、依赖追踪、局部失效、懒加载、缓存、批处理、后台合并和分段持久化。选择哪种方式取决于实际瓶颈和现有代码，不需要额外 ADR 授权。
- 增量实现必须保留 revision 或等价的一致性标识，能够识别落后、缺失或损坏的投影；失败不得静默返回旧知识。
- 全量重建保留为首次构建、手动诊断、版本迁移、缓存损坏修复和一致性核验入口，不进入正常生成与编辑的同步热路径。
- 增量更新失败时应显式报错并提供重试、局部修复或全量重建路径。可以为可用性短暂降级，但必须可观察，不能吞错或把旧结果冒充最新状态。
- 相关优化至少验证：受影响记录正确更新、无关记录不被重写、增量结果与全量重建结果等价、落后或损坏状态可检测并恢复。

### Knowledge Command 与外部修改

- UI 与 Agent 通过统一的 Knowledge Command 和校验逻辑写入 Story Knowledge，校验覆盖 schema、稳定 ID、引用、证据和 revision。
- `requiresReview` 只表示某条知识写入未满足数据完整性条件。它不是 Full Access 审批，也不限制索引、WIKI 或存储实现的性能优化。
- 合法外部修改可以在检测和校验后导入，并触发受影响投影的增量更新；非法修改必须显式报错，不得静默进入知识库。
- 新 Claim 状态机、持久审核中心、图数据库、事实存储迁移和额外记忆抽取模型调用仍属于高成本架构或产品变更，需要单独证据与决策。修复现有逻辑、优化热路径和减少全量重建不属于这些冻结项。

## 当前评测结论

### 固定模型下的写前构思与连续性（2026-11-04）

本轮按用户要求收缩此前逐渐扩大的写作流程，将 PC 端「构思与审稿」改为「写前构思」。保留 `storyCraftEnabled` 项目字段，默认开启且可关闭；旧项目缺少字段时默认开启，显式关闭、刷新和其他设置更新保留原选择。目标是在同一模型下，把额外调用集中用于安排人物经历与叙事详略，文学收益仍需实际正文验证。

- 直接新章正常为「读取资料 → 一次短构思 → 正文 → 保存 → 按需整理人物与线索」。开启构思时两次模型调用，关闭时一次；整理开启另加一次，严格字数修订与正文输出恢复另计。自动诊断、完整修订、核对和反馈重修已移出生产路径；旧 `story_craft_edit.rs` 仅在本地保留作历史追溯，未纳入当前源码提交或编译。
- 构思使用当前供应商与同一模型，低推理档（`low`），输出上限 8,192 tokens，包含可能的推理开销。候选简报目标 200—350 字、硬上限 1,000 字符，含作者事件合同不超过 1,400 字符。保留作者原句绑定与事实/候选区别，重点选择值得展开的经历、人物牵挂与回应、相关前事余波及可略写步骤，不强制成长、反转或每章呼应。
- 构思失败、截断或无效时不重试，沿用作者要求与已有资料生成并报告原因。取消后停止后续调用和项目写入。资料来源、哈希、省略与用量继续记录；未保存草稿对应的旧续写记录应排除。基础正文、字数与权限检查继续生效。
- 普通 Agent 通过 `StorydexCraftRead` 读取资料，在既有回合中简短构思，不自动审稿或启动重写循环。已有方案与明确局部修改可直接执行；作者主动要求审改时仍按指定范围处理。关闭开关不妨碍作者明确要求的创作或编辑。
- 三项共享写作指导由 1,978 字符缩至 1,678 字符，保留本书文风与作者要求优先。加强人物目标与私心/依恋并存、表达偏差、日常相处的关系价值、跨章余波与可选语境呼应；不采用固定镜头、对白配额、先甜后虐或固定收尾物件。作者已保存的自定义内容不会强行覆盖。
- 续写整理仍为一次既有调用，schema 不变。提取指导补充会影响后续回应的共同经历、亲近隔阂及有关系意义的习惯、话语与物件，保留人物对象、触发事件与原文依据；不能因有来源绑定就认定摘要理解正确。
- 研究依据、设计推论与限制见本地 [研究与机制映射](../output/playwright/story-craft-light-20261104/research/研究与机制映射.md)。公开访谈可启发机制选择，不能证明这些改动提高质量；没有逐章精读完整《龙族Ⅲ》，旧研究包中的能力百分比没有实验支持。本轮不追求复制作家文风、人物或桥段。

本轮真实模型与 Playwright 验证已完成：固定 `cline / deepseek-v4.1-flash-1017`，六篇开关对照与三章连续创作合计17次请求（正文9、构思6、整理2），无失败、无恢复或重跑。供应商返回输入46,856、输出59,819 tokens，各请求字段完整；未使用未核实单价换算费用。原用户模型配置哈希未变，隔离浏览器、服务及临时凭证已清理。

agent 对匿名正文的主观阅读略偏好日常、悬疑开启版，奇幻更偏好关闭版；不是真人盲测，三组各一次不足以给出稳定胜率，共享指导相对旧版也没有独立对照。连续三章有母女关系的局部承接，但主体仍偏维修流程，图纸外楼层/日落纸灰规则未进入故事，白布袋只重现未澄清，位置矛盾被后文沿用。上下文证据确认原设定、近期正文和观察记录均纳入且未截断，不能把来源读取成功等同于模型正确理解。三章没有连续关闭对照，也没有超出近期原文窗口。

结论是工程调用边界及开关持久化可用、文学效果有得有失，**尚未证明稳定改善长篇质量**。当前保留轻量可关闭选项，不恢复复杂审稿循环，也不以单元测试、禁词数或 AI 检测器分数代替阅读判断。完整正文、匿名阅读、费用统计和工程验证见本地 [本轮实测报告](../output/playwright/story-craft-light-20261104/REPORT.md)。此前六篇指导对照没有稳定赢家，跨最近三章窗口的记录注入也不等于伏笔已稳定回收。

### 早前复杂审稿流程的历史证据（2026-11-04）

下列记录属于本轮收缩前的实现与试验，不定义当前默认流程。旧链路包括短构思、正文、诊断、按需完整修订与核对，明确拒绝时最多再反馈修复、核对各一次；开启整理后通常四至八次调用，诊断恢复、字数修订和正文恢复另计。曾使用构思/诊断/核对各 16,384、修订 32,768 tokens 的输出预算。旧协议详情见本地 [修改前说明](../output/playwright/story-craft-light-20261104/before/docs/writing-continuity.md)。

首轮通过可见浏览器调用 Cline 的 `deepseek-v4.1-flash-1017`，连续生成《退场之前》五章，共 20 次模型调用。第三章修正过交接出席矛盾与问答错位，第二章修订也曾新增未证前史、混淆说话人；第四章留下未修复的车辆时间冲突，第五章流程完成。普通 Agent 一次局部说话人修正完成后更新并核验记录，使用 9 次调用；另一次因测试操作者误按内部回合上限停止而回滚，也使用 9 次，因此首轮总计 38 次。不能把替换成功等同于修改有效，也不能隐藏中止开销。

首轮正文可见局部选择后果，但事务安排过密、情绪展开不足，还出现把公开放映不点名扩展为值班册已约定不记名的错误推断。完整正文与调用证据见 [首轮报告](../output/playwright/story-craft-20261104/REPORT.md)。供应商未完整报告正文用量，历史成本不能凭缺失数据补成精确总额。

后续调整不断拆分诊断、修订与核对，仍遇到场面修改未应用、截断、上游超时、核心事件未落实与含糊同意。影院第二章与悬疑首章有局部可读性；影院第二章好处主要来自首稿，审稿失败，不能归功于后续修订。影院第三章仍有时序与衔接问题，最后一轮修订 HTTP 524 超时，留下带问题的原稿。新输入、正文和每次调用保留在 [后续调整目录](../output/playwright/story-craft-rework-20261104/)，不是严格对照实验，也没有证明稳定改善连续章节质量。

此前篇幅实验中的 beat 配额、条件式第二稿、tier 的 `NO-GO` 仍作为对应版本与实验条件下的历史依据。本轮不恢复旧配额或语义评分门禁，不能因为流程变短就预先宣称写得更好。当前操作与成本边界见 [写前构思与续写记录](writing-continuity.md)。

### Memory 与 WIKI

- T2 四臂 Memory/WIKI 评测没有稳定赢家，旧评测不足以翻转产品默认值。
- 可以继续做隔离实验、Trace、增量索引和检索性能优化；实验配置不得无意持久化为用户默认值。
- 新增模型、Embedding 或 reranker 到默认链路前，需要报告调用次数、token、延迟、失败和质量收益。纯本地确定性优化不受该前置条件限制。

### 篇幅控制

2026-10-28 按用户选择调整当前产品行为：

- 默认采用简短的篇幅和情节展开提示，目标字数始终可编辑；短/中/长仅为 1500/3000/6000 字的快捷选择。
- “严格字数检查”复用 `preciseWordCountEnabled`，新项目默认关闭，已有项目保留已保存选择。关闭时只作篇幅提示，完整正文不因偏短或偏长被拒写，也不自动修订。
- 用户开启后按目标 ±10% 验收，最多一次修订；仍不达标保留候选稿。移除固定场景配额与长章节第二次修订。空正文、截断、非法格式、写入权限及文件冲突检查不随开关关闭。
- 此次调整改变用户可选行为，不代表真实模型字数命中率或正文质量已获验证；保留下列历史实验结果，不能用确定性测试代替质量评估。
- 第四轮实测字数行为通过（引导模式 6709 字落盘，严格模式 6387 字首稿达标）。后续代码核对发现直接章节生成缺失项目上下文，已补接最近一章、相关角色/设定/脚本及编译预设，实际内容进入供应商消息并记录来源；不新增模型调用。它只修复上下文传递缺口，真实连续性收益尚未复测，详见 `reliability-round4-review-20261028.md`。

此前实验结论：

- beat 配额假设已被证伪，不恢复逐 beat 字数、更多 beat 类型或语义 Judge。
- 条件式第二稿和非对称门禁满足调用与写入合同，但真实正文质量不足。
- 最新 tier 正式验收为 `NO-GO`。16 个正式样本的调用效率、写入安全和提示隔离通过，但人工绝对质量仅 2/16，三档与两档分离均未通过。
- 当时推荐配置为 `no_tiers`，无档位 baseline 同样没有获得发布放行。
- 主要问题是正文事实连续性，包括经济状态、既有经历、时空方向和任务收束，不是单纯长度控制。后续评估须同时观察连续性，不以单个好样本翻转历史结论。

## 维护规则

- 当前决策变化时直接更新本文，并记录日期和必要证据；不为容易回滚的实现细节新增 ADR。
- 只有难以逆转、缺少背景会令人困惑且存在真实取舍的决定，才单独新增 ADR。
- 被替代的计划、ADR 和评测明细进入本地忽略的 `local/archive/` 或外部归档，公开仓库不同时保留多份互相冲突的“当前方案”。
- CI 使用确定性测试、契约和可再生 smoke 资产作为门禁；真实模型随机输出和本地大体量评测工作区只作为人工或发布证据，不直接作为普通提交的脆弱断言。
