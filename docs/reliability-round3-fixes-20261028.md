## 已完成

### 队列与项目隔离

- 四处以 action `this` 为身份的 WeakMap 统一经 `toRaw(store)` 访问：设置写队列、草稿写队列、草稿修订号、草稿累计变更。Pinia 开发插件每次新建 Proxy 也能找到同一队列；不同 Pinia 实例仍各自隔离。
- 章节完成状态写入纳入相同设置队列，不再绕过排队，也不在任意失败后改用完整设置写入。切项目会等待设置和最新草稿全部完成。
- 设置 GET/PUT、章节完成 PUT 及设置文件回退读取均携带 `workspaceRoot`。Rust 使用既有的项目路径解析与权限检查，已切到 B 的普通运行时拒绝迟到的 A 请求；隔离测试模式按既有边界规则解析到明确指定的 A，均不会误写 B。旧客户端不传该字段时保持兼容。
- 设置 GET 增加请求序号，旧 GET 成功或失败、写入之前发出的 GET、旧项目 GET 均不能覆盖新状态。读取失败保留已确认设置。
- 项目轮询只能更新当前项目的信息，不能直接将 A 的草稿绑定到后端刚切换的 B；旧项目的 health/project/tree 失败响应不会覆盖新项目提示。

### 设置失败提示

- 分开保存读取错误与写入失败状态。后台读取成功不会清除写入失败，直到下一次成功写入、用户点“知道了”，或正式切换项目。
- 失败仍回到已确认设置；开始重试时也不会提前隐藏上一次失败。
- HTML 声明现有 `favicon.svg`，消除浏览器默认请求 `/favicon.ico` 的 404。

### 章节篇幅：简短引导和可选检查

同日根据用户反馈及仓库历史评测重新简化，以下为当前实现，替代此前的固定场景配额和第二次修订方案。

- 目标字数始终可编辑，短/中/长快捷选择设置为约 1500/3000/6000 字。提示只说明目标及展开既有冲突、行动反应、人物决定和后果，不规定场景数量或逐段配额。
- “严格字数检查”复用 `preciseWordCountEnabled`。新项目默认关闭，已有项目保留用户选择，目标字数与开关分别保存。
- 关闭：目标仍传给模型，但仅为提示；不因字数偏差拒写，不自动发起修订，完整正文按实际篇幅落盘。没有目标值的旧档位请求同样不执行长度门禁。
- 开启：要求目标 ±10%，最多一次修订；仍不达标保留候选稿，不写入章节。失败、截断、格式异常或长度更差的修订不覆盖完整初稿。
- 两种模式均保留空稿、输出截断、格式、结构、权限和文件写入保护。关闭检查时，空稿或截断也不会发起额外调用；截断片段明确标记。
- 生成请求、TurnContract、测量及结果提示携带目标和开关。关闭时不会将字数偏差显示成“档位未命中”警告；严格模式的界面验收范围也统一为 ±10%。
- 持久化测试额外发现并修复：只提交字数开关的设置 PUT 不再清空未传入的章节完成状态；显式提交完成状态表时保持原有替换语义。
- 输出预算未继续上调。真实 6000 字命中率仍未验证；第三轮的一次失败不足以定义模型单次输出上限。研究材料保存在 `output/research/length-control-20261028/`。
