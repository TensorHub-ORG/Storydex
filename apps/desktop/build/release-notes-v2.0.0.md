# Storydex v2.0.0

Storydex v2.0.0 是一次面向 Agent 执行能力、长篇创作流程和桌面端稳定性的重大升级。

本版本将 Agent 执行核心迁移到内置的 Coomi Rust Runtime，重新整理任务执行、追问衔接、上下文治理和章节正文处理流程；同时改进项目搜索、文件管理、编辑体验、本地版本控制与应用内更新。

相比 v1.0.0，v2.0.0 更注重复杂任务能否稳定完成、执行过程是否清晰，以及正文、角色资料、WIKI 和项目文件之间能否保持一致。

## 主要更新

### Agent 执行核心

- Agent 执行核心升级为内置的 Coomi Rust Runtime，并通过 Storydex 专用的 `storydex-coomi-bridge` 与应用后端连接，不再依赖旧版 Python Coomi wheel。
- 重新整理 Agent 回复界面和流式执行状态，接受请求、分析、调用工具、等待、完成、取消与异常等阶段更容易辨认。
- 新增统一的任务执行协调机制，集中处理任务完成、失败、取消、回滚和会话收尾，减少中断后的状态残留。
- 改进执行期间的追问和后续指令处理，新消息可以等待当前任务到达合适阶段后继续执行，降低追问丢失或重复处理的概率。
- 计划模式现在只在用户明确提出规划需求时进入，普通问答和直接操作不会被意外转入计划流程。
- 优化 Agent 意图识别、响应速度和异常信息展示，执行失败时提供更明确的定位信息。

### 正文生成与篇幅处理

- 重构章节正文的生成、校验和写入流程，统一处理章节结构、剧情约束、上下文预算、正文质量与文件落盘。
- 正文生成会记录实际字数并执行必要的安全校验，但不承诺精确命中目标字数。
- 经过多轮字数控制方案试验后，当前版本不再因为篇幅未命中而无限补写、反复改写或重建整章，优先保证正文完整性、连贯性和执行可控。
- 加强对提纲、解释文字、工具输出包装和不完整正文的识别，避免将非正文内容误写入章节文件。
- 改进续写、改写和章节修订流程，修复追加写入、已有正文基线、异常恢复和重复内容处理中的问题。
- 短、中、长篇幅档位仍属于默认关闭的实验能力，不作为 v2.0.0 的正式功能发布。

### 上下文与会话衔接

- 新增执行级上下文策略，可根据本轮任务决定是否使用 Memory、WIKI、角色资料、预设和项目文件。
- 优化长篇项目的上下文装配，优先选择与当前任务相关的内容，减少无关资料占用模型上下文。
- 上下文窗口可按所用模型进行配置，Agent 会据此管理上下文预算和压缩时机。
- 改进会话回放、任务恢复和后续消息衔接，降低长任务中断后上下文错位或执行状态不一致的问题。
- 加强不同 Provider 和 OpenAI 兼容接口的处理，模型配置、请求参数和错误反馈更加稳定。

### WIKI 与创作一致性

- 改进 WIKI 生成、增量更新和审阅流程，使人物、地点、势力、物品、事件与关系的整理更加稳定。
- 加强正文、角色文件、事实记录、关系数据和知识图谱之间的增量同步，减少重复条目和缺少依据的覆盖。
- 优化关系语义、来源证据和变更判断，重要设定更容易追溯到对应项目内容。
- 修复 WIKI 操作与 Agent 会话之间的兼容问题，执行完成后项目状态和工作台显示能够及时更新。
- 改进知识图谱布局和交互稳定性，降低复杂关系图中的节点拥挤与状态不同步问题。

### 搜索、编辑与文件管理

- 新增项目级全文搜索，可搜索整个项目中的中文短语、常用文本和源码内容，并从结果直接打开对应文件。
- 新增文件内查找，支持匹配数量、全部结果高亮、当前结果强调，以及上一个、下一个结果定位。
- 资源管理器新增文件和文件夹多选、连续选择与批量拖动，整理大型项目目录更方便。
- Agent 回复中引用的项目文件可以直接在中央编辑区打开，减少手动查找文件的步骤。
- 新建项目时可选择规范架构或自由架构；规范架构项目支持按剧情、角色、世界背景、剧本、预设和模板分类浏览。
- 编辑器新增多种字体样式，并改进各工作区面板的字体缩放、输入焦点和布局稳定性。
- 优化顶部搜索、命令面板、新建项目窗口和 Agent 面板的交互细节。

### 本地版本控制

- Git 面板新增分支创建与切换，空仓库也可以在首次提交前创建目标分支。
- 改进提交记录、变更审阅、分支状态和错误信息展示，使提交失败原因更容易定位。
- 修复 Agent 自动提交被 `.storydex/.cache/` 等 Git 忽略目录阻断的问题。
- 完善运行缓存、日志和临时文件的忽略规则，减少无关文件进入项目版本记录。
- 保留恢复旧提交前创建本地备份分支的保护机制，并加强相关状态处理。

### 桌面端更新与恢复

- 重构应用内更新界面，检查、下载、等待安装、安装完成和失败恢复状态更加明确。
- 更新安装由独立辅助程序接管；主程序退出后继续执行安装，避免更新过程中程序文件被占用。
- 新增安装锁和恢复处理，防止应用在半更新状态下启动；安装失败时会保留旧版本和诊断日志。
- 改进后端启动检测、端口冲突处理和失败重试，桌面端启动异常后不再直接静默退出。
- 加强桌面进程清理，减少退出后残留的后端、Agent 或测试进程。

### 封装与发布质量

- Windows 正式版本会构建并内置 Coomi Rust Runtime、前端、后端、Python 3.9 和 MinGit，无需用户另外安装运行环境。
- 正式安装包和主程序执行 Windows 代码签名，并在发布前验证签名有效性。
- 加强嵌入式 Python 依赖锁定、运行时导入检查和封装资源扫描，避免开发缓存、测试文件、日志或环境文件进入正式包。
- 发布流程增加完整质量门禁，覆盖后端、前端、桌面端、Rust 构建、封装后启动和更新契约。
- CI 对覆盖率基线执行持续校验，并保留测试报告、覆盖率结果和失败诊断产物。

## 升级说明

- 已安装 v1.0.0 或其他旧版本的用户，可打开“系统设置 -> 更新与关于”检查更新，也可以下载 v2.0.0 安装包覆盖安装。
- 首次通过应用内更新升级时可能需要下载完整安装包；具备上一版安装包缓存后，后续更新可使用差分下载。
- 便携版用户请将新版本解压到独立目录，不建议与旧版程序文件混合使用。
- 小说项目、会话记录和 Provider 配置位于应用安装目录之外，正常覆盖安装不会删除创作数据。
- v2.0.0 更换了内置 Agent Runtime，但不需要用户单独安装 Rust、Python、Git 或 Coomi 组件。
